모델과 알 수 없는 필드

RangerPolicy는 불변 모델입니다. 고칠 때는 toBuilder()로 복사본을 만듭니다. Ranger 버전마다 정책 JSON에 필드가 더 있을 수 있는데, SDK는 모르는 필드도 보관했다가 저장할 때 그대로 돌려보냅니다. 그래서 오래된 SDK로 새 Ranger의 정책을 고쳐도 필드가 사라지지 않습니다.

쓰기 메서드 비교

버튼하는 일
update (버전 확인)저장 전에 서버의 현재 version과 비교합니다. 다르면 RangerConflictException.
update (확인 안 함)나중에 쓴 쪽이 이깁니다(last write wins).
apply(서비스, 이름)으로 찾아 있으면 고치고 없으면 만듭니다.
serverApplyRanger의 /policy/apply. 같은 리소스의 정책에 항목을 합칩니다.
createid·guid·version을 지우고 새 정책으로 만듭니다. 이름을 바꾸지 않으면 409.

따라 해 보기: 동시 수정 감지

  1. 설명(description)을 고치고 update (버전 확인)를 누릅니다. 성공합니다.
  2. 새로 고치지 않고 다시 고쳐 같은 버튼을 누릅니다. 편집기의 version이 낡았으므로 실패합니다.
  3. 실패 상자에서 예외 타입 RangerConflictException과 HTTP 409를 확인하세요.
화면 아래 요청 기록을 펼치면 update가 GET(현재 버전 확인) 뒤에 PUT을 보내는 것을 볼 수 있습니다.

이 화면이 쓰는 API

RangerPolicy p = admin.policies().get(12L);
RangerPolicy changed = p.toBuilder().description("new").build();
admin.policies().update(changed);          // 버전 확인 (= update(changed, true))
admin.policies().update(changed, false);   // 확인 안 함
admin.policies().delete(12L);
