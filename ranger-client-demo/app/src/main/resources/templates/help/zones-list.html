보안 영역이란?

한 서비스(예: demo_hive)의 정책은 보통 서비스 관리자가 모두 관리합니다. 그런데 재무 데이터처럼 다른 팀이 따로 관리해야 하는 리소스가 있으면, 그 리소스를 보안 영역으로 떼어 냅니다.

서비스 demo_hive
 ├─ (영역 없음)      database=sales …   ← 일반 정책
 └─ 영역 finance     database=finance   ← finance 영역의 정책만 적용
      관리자 admin · 감사자 admin
  • 영역에 속한 리소스에는 그 영역의 정책만 적용됩니다. 영역 밖 정책은 영향을 주지 않습니다.
  • 영역마다 관리자(admins)와 감사자(auditors)를 따로 둡니다.
  • 리소스 하나는 한 영역에만 속할 수 있습니다.
  • 태그 서비스를 영역에 연결하면 태그 기반 정책도 영역 단위로 나뉩니다.

이 화면 사용법

  • 목록 위의 두 결과는 가벼운 headers()(id와 이름만)와 영역 전체를 읽는 stream()입니다.
  • 영역 만들기: 서비스 하나와 리소스 하나(종류=값)로 영역을 만듭니다. 입력한 사용자가 관리자·감사자가 됩니다.
  • 부분 수정: 영역 전체를 다시 보내지 않고, 리소스·관리자·태그 서비스를 더하거나 뺍니다.
  • 이름을 누르면 영역 상세(JSON 편집, 리소스 목록)로 갑니다.

따라 해 보기

  1. 영역 만들기의 기본값으로 create를 누릅니다. sdk_demo_marketing 영역이 생깁니다.
  2. 리소스를 database=finance로 바꾸고 이름을 바꿔 다시 만듭니다. finance 영역이 이미 가진 리소스라 RangerValidationException(400)이 납니다.
  3. 부분 수정에서 영역 sdk_demo_marketing, 리소스 database=marketing_archive로 updatePartial을 누르면 리소스가 하나 더 붙습니다.
  4. deleteByName으로 sdk_demo_marketing을 지웁니다.
시드 영역 finance는 다른 화면 예시에서 쓰므로 지우지 마세요.

이 화면이 쓰는 API

List<Map<String, Object>> headers = admin.zones().headers();
List<RangerSecurityZone> zones = admin.zones().stream().toList();

RangerPrincipal me = RangerPrincipal.builder().type("USER").name("admin").build();
admin.zones().create(RangerSecurityZone.builder().name("sdk_demo_marketing")
        .services(Map.of("demo_hive", ZoneService.builder().resources(List.of(
            ZoneServiceResource.builder().resource(Map.of("database", List.of("marketing"))).build()))
            .build()))
        .admins(List.of(me)).auditors(List.of(me))
        .build());

long id = admin.zones().getByName("sdk_demo_marketing").getId();
admin.zones().updatePartial(id, SecurityZoneChangeRequest.builder()
        .adminsToAdd(List.of(RangerPrincipal.builder().type("USER").name("alice").build()))
        .build());
admin.zones().deleteByName("sdk_demo_marketing");

v2 API(/service/public/v2/api/zones-v2)를 씁니다. Ranger가 이 API를 지원하지 않으면 SDK는 UnsupportedFeatureException을 던집니다.
