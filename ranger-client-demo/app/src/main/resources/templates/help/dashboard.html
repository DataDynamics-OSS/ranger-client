데모 구성

docker compose가 Ranger 서버 세 종류를 띄우고, 이 앱은 SDK 클라이언트 세 개로 각각에 연결합니다.

demo-app ── RangerAdminClient ──▶ ranger-admin :6080  정책·서비스·사용자 관리
         ├─ RangerPdpClient   ──▶ ranger-pdp   :6500  권한 판단(authorize)
         └─ RangerKmsClient   ──▶ ranger-kms   :9292  암호화 키 관리
서버무엇을 하나
Admin정책, 서비스, 역할, 사용자·그룹, 보안 영역, 태그를 저장하고 REST API로 관리합니다.
PDPAdmin에서 정책을 내려받아 "이 사용자가 이 리소스에 이 권한이 있나?"에 답합니다.
KMSHDFS 암호화 영역 등에 쓰는 키를 만들고 돌리고 암복호화합니다.

연결 표 읽는 법

  • URL: 클라이언트에 설정한 서버 주소들. 여러 개면 SDK가 장애 조치(failover)합니다. 실패한 노드는 잠시 쿨다운으로 빠졌다가 돌아옵니다.
  • 인증: Admin은 basic, PDP는 신뢰 헤더(X-Forwarded-User), KMS는 Hadoop simple 인증입니다.
  • 확인: 서버마다 가벼운 호출을 하나 해서 UP인지 봅니다. 아래 "확인에 쓴 SDK 호출"에서 코드와 결과를 볼 수 있습니다.

기능 감지

Ranger 버전마다 있는 API가 다릅니다. SDK는 기능(Feature)을 쓰기 전에 서버가 지원하는지 한 번 확인해 기억하고, 없으면 HTTP 404 대신 뜻이 분명한 UnsupportedFeatureException을 던집니다. 서버 버전을 알면 ranger.admin.server-version으로 알려 줘 확인 요청을 줄일 수 있습니다.

데모 데이터

앱이 시작할 때 SDK로 다음을 넣습니다. 모두 upsert이므로 시드 다시 실행을 눌러도 안전합니다.

  • 사용자 alice, bob, mallory (비밀번호 Demo1234!), 그룹 analyst, engineer
  • 서비스 demo_hive(Hive), demo_tag(태그 서비스)
  • Policy as Code로 넣은 demo_hive 정책과 역할
  • 보안 영역 finance, 태그 PII, KMS 키 demo-key

이 화면이 쓰는 API

boolean hive = admin.serviceDefs().find("hive").isPresent();
Map<String, Object> ready  = pdp.ready();
Map<String, Object> status = kms.status();
Map<URI, Boolean> nodes = admin.nodeAvailability();   // URL별 사용 가능 여부

String version = admin.capabilities().serverVersion();
boolean zonesV2 = admin.capabilities().supports(Feature.ZONES_V2);
