역할이란?

역할(role)은 구성원 목록에 이름을 붙인 것입니다. 정책에 사용자를 하나하나 적는 대신 역할을 적으면, 구성원이 바뀌어도 정책은 그대로 둘 수 있습니다. 그룹과 달리 역할은 Ranger 안에서만 관리되고, 다른 역할을 구성원으로 가질 수 있습니다.

역할 analysts
 ├─ 사용자  alice
 └─ 그룹    analyst  (→ 그룹에 속한 사용자 모두)

정책 sales_read 허용: role analysts → select

역할 관리자 (★)

구성원 중 isAdmin이 켜진 사람은 그 역할의 구성원을 바꿀 수 있습니다(grant/revoke). 표에서 ★로 표시합니다.

apply와 grant/revoke

방법무엇을 하나
apply역할 전체를 이 값으로 만듭니다(관리 도구, Policy as Code 방식).
grant / revoke구성원을 더하거나 뺍니다. Hive의 GRANT ROLE SQL처럼 플러그인이 보내는 방식이며, grantor의 권한을 확인합니다.

따라 해 보기

  1. forUser를 alice로 눌러 보세요. 시드 역할 analysts가 나옵니다.
  2. grant로 bob을 analysts에 넣고, 다시 bob으로 forUser를 해 봅니다.
  3. revoke로 되돌립니다.
  4. apply로 sdk_demo_auditors를 만들고, deleteByName으로 지웁니다.
analysts는 시드 정책이 쓰는 역할입니다. 구성원을 바꾸면 PDP 권한 확인 결과도 바뀝니다.

이 화면이 쓰는 API

List<RangerRole> roles = admin.roles().search("demo", 0, 200);

admin.roles().apply(RangerRole.builder().name("sdk_demo_auditors")
        .users(List.of(RoleMember.of("bob"), RoleMember.admin("admin")))
        .groups(List.of(RoleMember.of("engineer")))
        .build());

admin.roles().grant("demo_hive", GrantRevokeRoleRequest.builder()
        .grantor("admin").targetRoles(List.of("analysts"))
        .users(List.of("bob")).build());

List<String> mine = admin.roles().forUser("alice");
List<String> all = admin.roles().names();
admin.roles().deleteByName("sdk_demo_auditors", null, null);
