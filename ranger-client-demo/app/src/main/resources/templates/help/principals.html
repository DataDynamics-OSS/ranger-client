주체(principal)

정책 항목은 사용자, 그룹, 역할에게 권한을 줍니다. 사용자와 그룹은 보통 LDAP/AD에서 usersync가 동기화해 오지만(출처 "외부"), 이 데모처럼 Ranger에 직접 만들 수도 있습니다(출처 "내부").

그룹 analyst  ── alice
(mallory는 그룹 없음: sales_read의 거부 항목 대상)
그룹 engineer ── bob
역할 analysts ── alice, 그룹 analyst

PDP는 요청에 그룹이 없으면 여기 저장된 구성원 정보로 사용자의 그룹을 찾습니다(데모 PDP는 use.rangerGroups=true).

Ranger 권한과 정책 권한은 다릅니다

구분뜻
Ranger 권한 (ROLE_USER …)Ranger 관리 화면에서 무엇을 할 수 있는지. ROLE_SYS_ADMIN은 모든 관리 가능.
정책Hive 등 데이터에 무엇을 할 수 있는지

이 화면 사용법

  • find는 없으면 빈 Optional을 돌려줍니다. 예외가 아닙니다.
  • 강제 삭제를 끄면 Ranger는 사용자/그룹을 숨김 처리만 합니다. 켜면 완전히 지웁니다.

따라 해 보기

  1. 사용자 carol을 create, 그룹 auditor를 create합니다.
  2. addUser로 carol을 auditor에 넣고 사용자의 그룹으로 확인합니다.
  3. 같은 이름으로 다시 create하면 RangerConflictException이 납니다. 오류 상자를 확인하세요.
  4. 정리: removeUser 후 강제 삭제를 켜고 각각 deleteByName.
시드 사용자 alice, bob, mallory와 그룹 analyst, engineer는 정책과 PDP 데모가 씁니다. 지우지 마세요.

이 화면이 쓰는 API

List<RangerUser> users = admin.users().search("a", 0, 100);
admin.users().create(RangerUser.builder().name("carol").firstName("Carol")
        .password("Demo1234!").userRoleList(List.of("ROLE_USER")).build());
Optional<RangerUser> carol = admin.users().find("carol");
List<RangerGroup> groups = admin.users().groups(carol.get().getId());

admin.groups().create(RangerGroup.builder().name("auditor").build());
admin.groups().addUser("auditor", "carol");
admin.groups().removeUser("auditor", "carol");
admin.users().deleteByName("carol", true);   // force
