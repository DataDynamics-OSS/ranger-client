무엇이 기록되나?

앱의 모든 SDK 클라이언트(admin, pdp, kms, 장애 실험용 lab-…)에는 기록용 인터셉터가 달려 있습니다. SDK는 HTTP 시도마다 인터셉터를 부르므로, 재시도나 장애 조치로 같은 호출이 여러 번 나가면 시도마다 한 줄씩 남습니다. 최근 300건까지 보관합니다.

열뜻
#앱이 시작된 뒤 기록 순서
클라이언트요청을 보낸 클라이언트 이름
경로누르면 전체 URI, X-Request-Id, 요청·응답 본문이 펼쳐집니다.
시도같은 호출 안에서 몇 번째 시도인지
상태HTTP 상태 코드. 응답을 받지 못했으면 "연결 실패"

실패한 줄(4xx/5xx, 연결 실패)은 빨간색입니다.

본문은 어떻게 얻나?

SDK의 RequestInterceptor.Attempt에는 본문을 받는 기본 메서드가 있습니다. 요청 본문은 보내기 전에 onRequestBody(contentType, body)로, 응답 본문은 onResponse(int status, byte[] body)로 들어옵니다 (이 메서드를 오버라이드하지 않으면 기존 onResponse(int)가 불립니다).

본문에는 비밀번호나 KMS 키 자료 같은 비밀이 들어 있을 수 있습니다. 이 데모는 요청 본문의 password 류 필드를 Masking.body()로 가리고, 본문은 2만 자까지만 보관합니다. 운영 코드에서 본문을 로그로 남길 때도 같은 주의가 필요합니다.

이 화면 사용법

  • 클라이언트로 걸러 보세요. 예: lab-failover만 보면 장애 조치 시도만 남습니다.
  • 기록 지우기는 이 앱의 메모리 기록만 지웁니다. Micrometer 지표는 그대로입니다.
  • 지표는 스타터가 등록한 ranger.client.requests 타이머와 ranger.client.retries 카운터입니다. /actuator/prometheus에서도 같은 값을 볼 수 있습니다.
  • 최근 SDK 호출은 화면들이 실행한 코드와 결과를 다시 보여 줍니다.

따라 해 보기

  1. 기록 지우기를 누릅니다.
  2. 장애 실험에서 ② 재시도를 누르고 돌아옵니다.
  3. lab-timeout 줄 세 개(시도 1·2·3)를 펼쳐 X-Request-Id가 같은지 봅니다.

이 화면이 쓰는 API

RequestInterceptor recorder = (server, method, uri, attempt, requestId, header) ->
        new RequestInterceptor.Attempt() {
            @Override
            public void onRequestBody(String contentType, byte[] body) { /* 보내기 전 */ }

            @Override
            public void onResponse(int status, byte[] body) { /* 응답을 받음 */ }

            @Override
            public void onError(Throwable error) { /* 응답 없음 */ }
        };

// 스타터가 만드는 클라이언트에 붙이기
@Bean
RangerAdminClientCustomizer record() {
    return builder -> builder.interceptor(recorder);
}
