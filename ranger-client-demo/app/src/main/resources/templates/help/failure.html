SDK 예외 계층

모든 SDK 예외는 RangerException(unchecked)을 상속합니다. HTTP 상태와 Ranger 응답에 따라 하위 타입이 정해지므로, 상태 코드를 직접 비교하지 않고 타입으로 처리할 수 있습니다.

예외언제
RangerNotFoundException404, 또는 Ranger가 "없음"을 다른 상태로 알려 줄 때(KMS 500 "key does not exist" 등)
RangerConflictException409, 이미 있는 이름, 버전 충돌
RangerValidationException400, 잘못된 요청 본문
RangerAuthenticationException401
RangerAccessDeniedException403
RangerServerException5xx (재시도 후에도 실패)
RangerTransportException응답 없음: 연결 거부, 시간 초과

오류 상자 읽는 법

  • 굵은 글씨: 예외 클래스 이름. 맨 아래 회색 글씨가 전체 이름입니다.
  • HTTP 배지: Ranger가 돌려준 상태 코드(응답을 받았을 때만).
  • 서버 메시지: Ranger가 응답 본문에 담은 오류 메시지.
  • X-Request-Id: SDK가 요청마다 붙이는 ID. Ranger 로그와 맞춰 볼 때 씁니다.

코드에서 처리하기

try {
    admin.policies().getByName("demo_hive", "no_such_policy");
} catch (RangerNotFoundException e) {
    // 없는 경우 처리
} catch (RangerException e) {
    log.warn("{} {} -> {} ({})", e.getMethod(), e.getPath(), e.getStatus(), e.getRequestId());
}
