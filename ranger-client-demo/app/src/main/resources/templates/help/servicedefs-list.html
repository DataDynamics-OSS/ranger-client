서비스 정의란?

Ranger는 여러 시스템(Hive, HDFS, Kafka, Trino …)의 권한을 한곳에서 관리합니다. 시스템마다 리소스와 권한이 다르므로, 그 모양을 정한 것이 서비스 정의(service def)입니다.

서비스 정의 hive          (스키마)
 └─ 서비스 demo_hive      (실제 Hive 클러스터 하나)
     └─ 정책 sales_read   (그 클러스터의 권한 규칙)

예를 들어 hive 정의는 "리소스는 database → table → column 계층이고, 권한은 select, update, create …"라고 정합니다. 정책에 이 정의에 없는 리소스나 권한을 쓰면 Ranger가 거부합니다.

표의 열

열뜻
리소스리소스 종류 수(database, table, column, udf, url …)
권한access type 수(select, update, …)
마스킹 / 행 필터마스킹·행 필터 정책을 지원하는지

이 화면 사용법

  • 이름을 누르면 리소스 계층, 권한, 마스킹 종류를 자세히 봅니다.
  • 정의는 Ranger에 기본으로 들어 있습니다. 데모에서는 읽기만 합니다.
목록 하나를 읽는 데도 요청이 여러 번일 수 있습니다. stream()이 페이지 크기만큼씩 끝까지 넘기기 때문입니다. 화면 아래 요청 기록에서 startIndex가 바뀌는 것을 확인하세요.

List<RangerServiceDef> defs = admin.serviceDefs().stream().toList();
