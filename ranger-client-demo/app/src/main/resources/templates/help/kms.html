Ranger KMS란?

Ranger KMS는 Hadoop KMS와 같은 REST API를 제공하는 키 관리 서버입니다. 주로 HDFS 투명 암호화(encryption zone)의 키를 보관합니다. 키는 KMS DB에 마스터 키로 암호화되어 저장되고, 누가 어떤 키 작업을 할 수 있는지는 Ranger Admin의 KMS 서비스(dev_kms) 정책으로 정합니다.

키, 버전, EEK

용어뜻
키 (key)이름이 붙은 키. 예: demo-key. 암호(cipher)와 길이를 가집니다.
키 버전실제 키 재료. 롤오버하면 새 버전이 생기고, 새 암호화는 새 버전을 씁니다. 옛 버전은 옛 데이터 복호화를 위해 남습니다. 버전 이름은 demo-key@0, demo-key@1 …
DEK파일 하나를 실제로 암호화하는 데이터 키
EEK키(영역 키)로 암호화된 DEK. 파일 메타데이터에는 EEK만 저장됩니다.
 
generateEek(demo-key)  → EEK (demo-key@0으로 암호화된 DEK)
decryptEek(EEK)        → DEK 평문 (decrypteek 권한 필요)
rolloverKey(demo-key)  → demo-key@1
reencryptEek(EEK)      → demo-key@1로 다시 암호화된 EEK (DEK는 그대로)

이 화면 사용법

  • 키 표의 버튼은 그 키에 대한 SDK 호출 하나씩입니다. 결과는 "결과" 아래에 나타납니다.
  • 키 만들기: 이름은 영문·숫자·_ . -만 됩니다. 만들면 키 표가 새로 고쳐집니다.
  • EEK: 고른 키로 generate → decrypt → (롤오버) → re-encrypt를 차례로 실행하고 단계마다 결과를 보여 줍니다.

따라 해 보기

  1. EEK에서 demo-key를 고르고 실행합니다. 결과의 versionName(EEK를 만든 키 버전)을 보세요.
  2. 키 만들기로 sdk_demo_key를 만들고, 표에서 rollover를 누르면 버전 수가 2가 됩니다.
  3. EEK에서 sdk_demo_key와 "롤오버"를 켜고 실행하면, re-encrypt 결과의 키 버전이 새 버전으로 바뀝니다.
  4. delete로 sdk_demo_key를 지웁니다. 지운 뒤 metadata를 다시 부르면 RangerNotFoundException입니다.
시드 키 demo-key는 지우지 마세요. 키를 지우면 그 키로 암호화된 데이터는 영영 복호화할 수 없습니다.

이 화면이 쓰는 API

List<String> names = kms.names();
List<KeyMetadata> meta = kms.metadata(names);

kms.createKey("sdk_demo_key", "AES/CTR/NoPadding", 128, "demo", Map.of("owner", "demo"));
KeyVersion v1 = kms.rolloverKey("sdk_demo_key");
List<KeyVersion> versions = kms.versions("sdk_demo_key");

List<EncryptedKeyVersion> eeks = kms.generateEek("demo-key", 1);
KeyVersion dek = kms.decryptEek("demo-key", eeks.get(0));
EncryptedKeyVersion moved = kms.reencryptEek("demo-key", eeks.get(0));

kms.deleteKey("sdk_demo_key");

KMS가 "키가 없다"를 500 오류로 알려 줘도 SDK는 RangerNotFoundException으로 바꿔 줍니다.
