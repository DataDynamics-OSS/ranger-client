서비스란?

서비스(service)는 서비스 정의의 인스턴스입니다. 예를 들어 Hive 클러스터가 두 개면 hive 타입 서비스도 두 개(prod_hive, dev_hive)를 만들고, 각 클러스터의 Ranger 플러그인은 자기 서비스 이름의 정책만 내려받습니다.

hive (정의) ─┬─ demo_hive  ← 이 데모의 Hive 플러그인/PDP가 쓰는 서비스
             └─ prod_hive
tag  (정의) ─── demo_tag   ← 태그 기반 정책 (demo_hive가 연결)

태그 서비스

서비스에 태그 서비스를 연결하면, 그 서비스의 리소스에 붙은 태그(예: PII)에 대한 태그 정책도 함께 평가됩니다. 시드의 demo_hive는 demo_tag에 연결되어 있습니다.

이 화면 사용법

  • 타입으로 거릅니다. 비우면 전체입니다. 예: hive, tag, kms
  • 만들거나 고치기: 설정은 한 줄에 key=value 하나입니다. 필수 설정은 서비스 정의마다 다릅니다(서비스 정의 상세의 "서비스 설정 항목").

따라 해 보기

  1. 기본값 그대로 apply를 누릅니다. sdk_demo_hdfs 서비스가 생기고 목록이 새로 고쳐집니다.
  2. 다시 apply를 눌러 보세요. 같은 id로 고쳐질 뿐 오류가 나지 않습니다.
  3. 이름을 눌러 상세 화면에서 testConnection과 delete를 해 봅니다.
서비스를 지우면 그 서비스의 정책도 모두 지워집니다. demo_hive, demo_tag는 지우지 마세요.

이 화면이 쓰는 API

List<RangerService> hive = admin.services().search("hive", Map.of(), 0, 200);
Stream<RangerService> all = admin.services().stream(null);

RangerService svc = RangerService.builder()
        .name("sdk_demo_hdfs").type("hdfs").tagService("demo_tag")
        .configs(Map.of("username", "hdfs", "password", "hdfs",
                "fs.default.name", "hdfs://namenode.example:8020"))
        .build();
admin.services().apply(svc);    // 이름 기준 upsert

새로 만든 결과는 "결과" 패널에서, 실제로 오간 요청(GET으로 있는지 확인 후 POST/PUT)은 결과 아래 요청 목록에서 볼 수 있습니다.
